# 플러그인과 프로젝트 규칙 업데이트

[English](updating.md)

프로젝트 규칙 업데이트 절차는 v0.2.0부터 제공됩니다. 스킬이 안내하는 절차이며 자동 마이그레이션 서비스가 아닙니다. 구조·manifest 검사는 통과했지만 실제 대화에서 승인·갱신 단계를 수행하는 시험은 아직 하지 않았습니다. 로컬 checkout을 시험하려면 `claude --plugin-dir .`로 불러옵니다.

## 서로 다른 두 가지 업데이트

1. **플러그인 파일**: Claude Code로 설치했거나 checkout에서 불러온 스킬·절차·템플릿입니다.
2. **프로젝트 규칙**: 이전에 프로젝트 `CLAUDE.md`로 복사한 짧은 podium 절입니다. 프로젝트가 소유하며 별도 결정이 들어 있을 수 있습니다. 플러그인을 업데이트해도 자동으로 바뀌지 않습니다.

“podium 업데이트해 줘”라고 하면 설치 경로를 확인하고 업데이트 계획을 준비합니다. “이 프로젝트의 podium 규칙을 갱신해야 하는지 확인해 줘”, “플러그인만 업데이트해 줘”, “프로젝트 규칙만 비교해 줘”로 범위를 지정할 수도 있습니다. 매 대화마다 업데이트를 확인하지 않습니다. 확인만 요청했다면 파일을 바꾸지 않습니다.

## 플러그인 설치 경로

마켓플레이스 설치는 실제 등록한 목록을 갱신하고 설치된 범위의 플러그인을 업데이트합니다. 기본 podium 마켓플레이스의 명령은 다음과 같습니다.

```bash
claude plugin marketplace update podium
claude plugin update podium@podium
```

로컬 checkout은 브랜치·태그와 미커밋 변경을 먼저 확인하고 대상 배포본·ref와 실행할 명령을 보여 줍니다. 개발 변경을 자동으로 pull하거나 브랜치를 바꾸거나 사용자 작업을 reset·stash하지 않습니다. 이전 태그에 고정한 목록이나 checkout의 대상 변경은 명시적으로 결정합니다.

업데이트 후 필요하면 플러그인을 다시 로드하거나 새 세션을 시작합니다. 이전 절차를 쓰는 세션은 새 템플릿을 비교했다고 말하면 안 됩니다. 새 버전의 마켓플레이스 배포 과정은 [버전 배포](releasing.ko.md)를 참고하세요.

## 프로젝트 규칙 갱신

절차는 관련 podium 절만 현재 불러온 플러그인의 짧은 템플릿과 비교하고, 프로젝트별 역할·승인·설정·파일 담당·대장 형식을 보존합니다. 실제 변경안을 보여 준 뒤 승인을 받습니다. 다른 세션 소유의 파일이면 직접 고치는 대신 담당자가 검토할 패치를 준비합니다.

새 템플릿에는 `<!-- podium:begin -->` / `<!-- podium:end -->`가 한 쌍 있습니다. 갱신 후보의 경계 표시이며 안쪽 내용을 전부 버려도 된다는 뜻이 아닙니다. 표시가 없는 기존 프로젝트는 제목을 기준으로 범위를 제안합니다. 경계가 불명확하거나 절이 중복돼 있으면 해결 전까지 그대로 두고 새 절을 추가하지 않습니다.

승인한 패치를 적용하려면 되돌릴 방법과 대상의 최신 상태를 확인해야 합니다. 합의한 줄만 바꿉니다. 업무 기록·진행 목록·세션 대장·현재 상황·worklog·설정은 새 템플릿으로 덮어쓰지 않습니다. 새 변경 없이 다시 비교하면 추가 편집이 없어야 합니다.

결과는 플러그인 버전과 프로젝트 규칙 변경을 구분해 알립니다. 실제 동작은 별도 시험이 필요하며 템플릿이 일치한다고 동작까지 검증된 것은 아닙니다. 업데이트에 세션 생성·메시지·이동·보관은 포함되지 않습니다.
