# 알림

- ID: W-01 / 이름: reminders
- 목표: 사용자가 할 일에 알림을 설정하면 제시간에 휴대폰과 데스크톱으로 알림을 받는다.
- 마감·일정: 베타 마감 2026-10-30, 기능 플래그 뒤에서 배포
- 핵심 문서: docs/reminders-spec.md (이 예시를 위해 지어낸 경로)

## 현재 상태
- 리서치(s-0004)는 끝났습니다. 푸시 서비스를 비교해, 휴대폰은 플랫폼 자체 푸시, 데스크톱은 웹 푸시를 쓰기로 했습니다. 자세한 내용은 "결정 기록"에 있습니다.
- 구현(s-0005)은 개발 환경에서 알림 모델과 스케줄러가 동작하고, 다음은 휴대폰 전달입니다.
- 정책 점검(s-0006)에서 방해 금지 시간과 미루기에 대한 질문 두 개가 나왔습니다("미결 사항" 참고).
- 화면(s-0007)은 디자인 파일을 기다리는 중이라 아직 검토할 것이 없습니다.

## 다음 할 일
- 구현: 휴대폰 전달을 끝내고 데스크톱으로.
- 정책: 사용자가 미루기 기한을 정하면 방해 금지 시간 규칙을 씁니다.
- 화면: 디자인 파일이 오면 시작합니다.

## 미결 사항
- 미룬 알림을 얼마 동안 두었다가 버릴까요? 선택지: 24시간(권장: 목록이 깔끔해짐), 7일, 계속 유지.
- 방해 금지 시간은 사용자별인가 기기별인가요? (정책 세션은 사용자별을 권장)

## 결정 기록
- 2026-10-14: 리서치, 구현, 정책, 화면으로 나눔. 이유: 구현과 정책은 동시에 진행하고, 리서치는 읽을 자료가 많고, 화면은 디자인 검토가 따로 필요함.
- 2026-10-15: 휴대폰은 플랫폼 푸시, 데스크톱은 웹 푸시를 사용 (근거: 리서치 요약, s-0004).
- 2026-10-17: 자동 요약이 일어난 관리자 세션을 교체함. 이 파일이 인계 문서.
